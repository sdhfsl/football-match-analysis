# football-match-analysis

足球赛前深度分析 Skill —— 从真实数据源抓取盘口、伤停、交锋与技术统计，输出**每个数字都能溯源**的结构化赛前报告。

## 为什么做这个

大多数"足球分析 Prompt 模板"有一个共同缺陷：它们用固定表格要求模型填满数字，却不告诉模型数字从哪来。结果是没有数据源的模型会**编出看起来合理的数字**——场均 xG、初盘水位、伤停名单，全是幻觉，而报告表面上非常专业。

这个 Skill 反过来做：**先把数据源摸清，再谈分析。** 拿不到就标注"不可得"，并区分是"源被拦"还是"数据根本不存在"。一份半边实、半边空但标注清楚的报告，比一份全填满的报告有用得多。

## 核心能力

- **四类盘口区分与判读**：竞彩让球（整数盘）、亚盘（半球/四分之一球）、欧赔、大小球。同一个"让 1 球"在竞彩与亚盘下含义完全不同，混为一谈是最常见的错误。
- **背离检查**：竞彩让 1 vs 亚盘 -0.5 之间的落差本身就是信号，本 Skill 会做隐含概率的一致性校验来确认读数正确。
- **动机不对称分析**：出线形势、必须赢 vs 可接受平局、赢下这场的下一轮对手是谁——往往比实力对比更决定结果。
- **用打法验证盘口**：技术统计（控球率、射门、角球）用来判断"这个盘口是否现实"，而不只是堆数字。
- **反幻觉纪律**：不可得清单是报告的必备部分。

## 安装

把整个目录放到以下任一路径（前者优先级更高）：

```
~/.zcode/skills/football-match-analysis/
~/.agents/skills/football-match-analysis/
```

或项目级：

```
<project>/.zcode/skills/football-match-analysis/
<project>/.agents/skills/football-match-analysis/
```

## 数据可得性（实测结论）

| 数据 | 可得性 |
|---|---|
| 竞彩让球数、胜平负、让球胜平负、各玩法是否开售 | ✅ |
| 亚盘 / 大小球 / 欧赔平均值 | ✅ |
| 伤停、停赛 | ✅ |
| 历史交锋（含赛事类型与比分） | ✅ |
| 技术统计：控球率、射门(射正)、角球、黄牌、红牌 | ✅ |
| 小组积分、赛果、大名单、射手榜、淘汰赛对阵 | ✅ |
| 出线形势与淘汰赛路径 | ✅（需自行推导） |
| 天气 | ✅ |
| 初盘 / 水位移动 | ❌ 公开源无此字段，**靠自行归档** |
| 初赔 → 即时赔变化 | ❌ 同一根因 |
| 预计首发 | ❌ 该级别赛前不存在 |
| xG / xGA | ❌ 此级别赛事无公开 xG（用射门(射正)作代理） |

## 编码的技法

- **被 WAF 保护的站点用真浏览器，不做逆向**：JS cookie 挑战（如 `acw_sc__v2`）用浏览器打开即可正常通过；但**交互式验证码不绕**，遇到就换源。
- **图表渲染的数据用 `evaluate` 读 DOM**：无障碍快照里看不到数值 ≠ 取不到。控制台选择器见 `references/sources.md`。
- **Wikipedia 的表格要用 HTML 解析**：`prop=extracts` 会剥掉全部表格，积分榜和赛果都在表格里。
- **批量取数**：浏览器调用昂贵，把多次导航串在同一个 JS cell 里。
- **归档盘口**：初盘无法回溯获取，唯一可靠办法是每次取数都存下带时间戳的基线，下次相减即为水位移动。
- **交叉验证**：关键事实至少两个独立源，时区换算最容易出错。

## 边界

- 不绕过交互式验证码。
- 报告仅用于赛事研究与数据讨论，**不构成投注建议**。
- 遇到与预期不符的数据（某队战绩远好于印象）照实呈现并解释来源，不为迎合预期而调整数据。
