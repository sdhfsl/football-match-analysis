## 写作要求

### 数据来源声明必须区分三种状态

这是本模板最容易被做假的地方。三种状态要写清楚：

| 状态 | 写法 |
|---|---|
| 已获取 | 写出来源，必要时写"交叉验证" |
| **数据不存在** | 「该级别赛事无公开 xG」——不要让读者以为是你没抓到 |
| **源被拦** | 写清哪个源、什么拦截、有没有换源重试 |

### 隐含概率要自己去水后再写

```python
raw = [1/o for o in odds]
probs = [r/sum(raw)*100 for r in raw]
```

同时给原始赔率。不要只给概率。

### 一致性校验要显式写出来

让读者能验证你的读数没错：

> 让胜 + 让平 = 73.2%，与非让球盘的主胜 72.1% 吻合，说明赔率内部自洽。

### 动机不对称单独成段

出线/保级/晋级形势导致的动机差异，往往比实力对比更决定比赛走向。必须回答：

- 谁必须赢？谁可以接受平局？
- 平局对各队分别意味着什么？
- **赢下这场之后对阵谁？** 下一轮对手的强弱会改变"争第一"的价值。
- 同组其他比赛什么时候出结果？如果比本场早，它是一个**有明确解出时间的不确定性**，要点名并给出解出时刻。

### 技术统计要转成"打法"结论

不要只堆数字。技术统计的价值在于判断盘口是否现实：

> 该队两场控球率 32%/31%，场均 2 个角球、7.5 次射门。要求它净胜 2 球违背其打法。

### 置信度敢给低

主胜与平局隐含概率接近、或结果依赖未出结果的变量时，**给"低"是正确的**。报告的价值在于讲清不确定性，而不是制造自信。

### 不得出现绝对化表达

禁止"必胜""稳胆""一定打穿""稳赢"。改为给出方向、概率区间与风险。

## 实例（节选，展示格式与颗粒度）

```markdown
### 4. 竞彩让球判断

| 市场 | 即时赔 | 隐含概率（去水后） |
|---|---|---|
| 让胜（主队赢 2+） | 4.50 | 19.7% |
| 让平（主队正好赢 1） | 3.45 | 25.7% |
| 让负（主队不胜） | 1.62 | 54.6% |

一致性校验：让胜 + 让平 = 45.4%，与非让球盘的主胜 43.8% 吻合，赔率内部自洽。

**判断：主判断「让平」，备选「让负」，明确回避「让胜」。**

理由：
1. 主队动机是"不输"而非"赢两个"——平局即出线。
2. 主队进攻产量支撑不了赢 2 球（两场 2 球，场均 1.00）。
3. 亚盘平均只给 -0.5，比竞彩的 -1 浅了一整球，且水位偏向客队受让。
4. 两次正式交锋比分都是 2-1（主队赢 1 球）。
```

**注意最后给了四条理由，其中第 3 条是"两个市场互相矛盾"的信号，第 4 条是历史剧本，第 1、2 条是动机与产量。** 结论要落到"为什么这个高赔方向不能碰"，而不只是"我选哪个"。
